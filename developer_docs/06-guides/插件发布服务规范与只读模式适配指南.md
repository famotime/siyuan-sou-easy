# 插件发布服务规范与只读模式适配指南

- 适用版本：SiYuan `v3.8.5`+ / npm `siyuan@1.2.8`+
- 最后核对：2026-09-25
- 稳定性：stable
- 官方规范参考：<https://github.com/siyuan-note/siyuan/blob/master/docs/PLUGIN-PUBLISH.zh-CN.md>

---

## 1. 背景与核心设计理念

思源笔记支持通过「发布服务」将笔记本公开发布为 Web 站点供访客浏览。在发布页面中，思源前端界面与已启用的插件同样会被加载执行。

在以往版本中，发布页面的环境与本地桌面端没有清晰的安全边界：
- 访客浏览器并非管理员身份，无法调用写接口；
- 插件若直接调用 `this.loadData()` 读取私有存储（`data/storage/`），会导致请求失败或意外泄露未授权配置；
- 若插件在只读端尝试执行写操作或建立双向 RPC，会导致控制台报错甚至界面崩溃。

为了解决这一问题，从 `v3.8.4` 起，思源官方正式推出了**插件发布服务架构（Plugin Publish System）**：
1. **公开数据快照机制**：公开数据是插件为发布端专门准备的一份**只读快照**，保存在独立的 `conf/plugin-publish/<name>.json` 中，与私有存储物理隔离。
2. **三步授权模型**：开启发布服务 → 开启插件发布开关 → 管理员单独授权数据字段。授权本身不自动复制私有配置，必须由插件主动调用 `savePublishData` 生成公开快照。
3. **严格只读与优雅降级**：发布页面读取快照失败（未授权或未生成）时，插件必须展示安全的默认内容，**绝对禁止尝试回退读取私有存储**。

## 2. plugin.json 配置规范

如果插件希望在发布页面中正常运行并展示内容，必须在 `plugin.json` 中进行声明：

```json
{
  "name": "my-plugin",
  "minAppVersion": "3.8.5",
  "disabledInPublish": false,
  "publish": {
    "resources": [
      "views/public.html",
      "images/logo.png",
      "fonts/"
    ],
    "data": [
      "theme",
      "headerTitle",
      "showAuthor"
    ]
  }
}
```

### 2.1 字段含义与约束

| 字段 | 类型 | 说明与规范要求 |
| :--- | :--- | :--- |
| `disabledInPublish` | `boolean` | 是否在发布页面中禁用本插件。设为 `false` 表示允许在发布页面加载。 |
| `publish.resources` | `string[]` | 发布端所需的额外静态前端资源相对路径列表。 |
| `publish.data` | `string[]` | 允许公开的数据字段名称列表。 |

### 2.2 resources 声明规则
- **标准入口自动包含**：根目录下的 `index.js`、`index.css` 以及 `i18n/*.json` 文件思源会自动提供，无需在 `resources` 中重复声明。
- **支持文件与递归目录**：支持声明具体的相对文件（如 `images/logo.png`），支持以 `/` 结尾的递归目录（如 `fonts/`）。
- **禁止项**：严禁声明 `plugin.json`、`kernel.js`、软链接（Symlink）、Windows 目录联接（Junction）或包含 `..` 上级跳转的路径。
- **数量限制**：最多声明 4096 个资源文件。

### 2.3 data 字段声明规则
- **仅允许标量类型**：字段值只允许为 `string`、`number`、`boolean` 或 `null`。**严禁声明复杂对象或数组**，避免因未来增加内部属性而隐式扩大公开权限。
- **命名规范**：仅允许 ASCII 字母、数字、`_` 和 `-`，长度不超过 128 字符。
- **大小限制**：单个快照编码后总大小不得超过 1 MiB。最多声明 128 个字段。

## 3. 插件类 API 与只读模式适配

### 3.1 环境检测

在插件的 `onload()` 中，首先通过全局状态判断当前运行环境：

```typescript
export default class MyPlugin extends Plugin {
  public isReadonly: boolean
  private publishDataStatus = ""

  async onload() {
    // 检测是否处于只读模式或发布服务页面
    this.isReadonly = Boolean((window as any).siyuan?.config?.readonly || (window as any).siyuan?.isPublish)

    if (this.isReadonly) {
      // 发布端逻辑
      await this.loadPublishedSettings()
      this.initReadOnlyUI()
      return // 提前结束，不注册写命令和内核通信
    }

    // 管理员端可写逻辑
    await this.initAdminUI()
  }
}
```

### 3.2 读取公开快照 (`loadPublishData`)

`loadPublishData()` 专门供发布端使用，返回管理员已授权并生成的公开快照：

```typescript
private async loadPublishedSettings(): Promise<void> {
  // 设置安全默认值
  this.data["config.json"] = { headerTitle: "默认标题", showAuthor: true }
  this.publishDataStatus = ""

  try {
    const snapshot = await this.loadPublishData()
    if (typeof snapshot?.headerTitle === "string") {
      this.data["config.json"].headerTitle = snapshot.headerTitle
    }
    if (typeof snapshot?.showAuthor === "boolean") {
      this.data["config.json"].showAuthor = snapshot.showAuthor
    }
  } catch (error: any) {
    const code = error?.code
    if (code === 403) {
      this.publishDataStatus = "公开数据尚未获管理员授权"
    } else if (code === 404) {
      this.publishDataStatus = "公开数据快照尚未生成"
    } else {
      this.publishDataStatus = "读取公开数据快照失败"
    }
    // ⚠️ 极其重要：读取失败时绝对不要调用 this.loadData("config.json")！
    console.warn(`[${this.name}] loadPublishData 异常:`, this.publishDataStatus)
  }
}
```

### 3.3 保存公开快照 (`savePublishData`)

`savePublishData()` 必须在管理员可写环境下调用。调用时会**完整替换**旧快照，未包含在参数中的字段会被移除：

```typescript
public async publishSettings(title: string, showAuthor: boolean): Promise<void> {
  if (this.isReadonly) {
    return
  }

  try {
    // 仅提交声明过的公开标量字段
    await this.savePublishData({
      headerTitle: title,
      showAuthor,
    })
    showMessage("公开数据快照保存成功！")
  } catch (error: any) {
    const code = error?.code
    if (code === 403) {
      showMessage("发布失败：需要管理员在插件卡片上点击授权按钮")
    } else {
      showMessage("保存公开快照失败")
    }
  }
}
```

### 3.4 生命周期安全防护

在 `onunload()` 和 `uninstall()` 中，增加只读防护：

```typescript
onunload() {
  if (this.isReadonly) {
    return // 只读发布端不执行外部清理
  }
  // 正常拆除监听器与组件...
}

async uninstall() {
  if (this.isReadonly) {
    return // 只读端无权卸载
  }
  // 删除私有数据...
  await this.removeData("config.json").catch(() => {})
}
```

## 4. 界面交互与错误状态码一览

思源内核针对插件发布接口统一返回 `{ code, msg, data }` 信封，开发者应依据状态码给予访客与管理员清晰的反馈：

| 状态码 (`code`) | 含义 | 访客端表现与建议处理 | 管理员端表现与建议处理 |
| :--- | :--- | :--- | :--- |
| `0` | 成功 | 正常渲染公开数据内容 | 提示保存/授权成功 |
| `400` | 参数或字段无效 | 提示数据格式错误 | 检查提交字段是否超出 `plugin.json` 声明范畴 |
| `403` | 未授权或插件不可发布 | 显示「数据不可用」或回退展示默认无害内容 | 提示管理员检查插件卡片的「发布服务」开关与「插件发布数据」授权 |
| `404` | 已授权但尚未生成快照 | 显示「尚未生成公开数据」或安全默认模板 | 提示管理员在插件设置中执行首次生成/发布操作 |
| `500` | 存储或内部错误 | 提示加载失败，提供刷新按钮 | 检查系统磁盘或日志 |

## 5. 验收测试清单

在发布插件新版本前，建议进行以下场景测试：

1. **全新安装测试**：在未开启发布服务前，确认插件正常运行。
2. **未授权测试**：开启发布服务并开启插件开关，但不点击数据授权，访问发布页面，验证插件是否优雅降级（呈现 403 处理，无红字控制台报错）。
3. **未生成测试**：完成字段授权，但尚未在插件中点击发布，访问发布页面，验证插件是否正常处理 404。
4. **生成并访问测试**：在管理端保存公开快照，刷新发布页面，确认公开字段正确呈现。
5. **撤销与关闭测试**：在管理端撤销数据授权或关闭插件发布开关，验证发布页面即刻停止获取数据。
